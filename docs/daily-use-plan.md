# Musaic 日常可用性计划（Daily-Use Plan v1.0）

> 日期：2026-09-12 ｜ 前置：`3a445a4`（P0/P1 清零 + CI + 架构守护 + S1 迁移框架）
> 目标：把 Musaic 从「功能齐备但动线断裂」推进到**可以日常使用**，最后做一轮完整测试。

---

## 0. 判断依据：按动线核对，而非按功能清单

体检方式是**以用户视角走一遍日常动线**，而非对照计划文档的 checkbox。
结论：缺的不是高级功能，而是**基础动线断裂**——功能都在，但入口不通。

四条动线及其断点：

| 动线 | 用户想做的事 | 断点（均有代码证据） |
|---|---|---|
| **找歌** | 搜、粘链接、粘 ID | 搜索框提示「搜索 / 链接 / ID」（`search_page.dart:142`），但 `_submit` 直接拿原始串去搜，**无任何解析实现** |
| **存歌** | 把正在听的歌加入歌单 | `addToPlaylist` 全项目**仅** `search_results_page.dart` 调用；播放页 / 小播放条 / 收藏 / 历史 / 歌单详情均无入口 |
| **管理** | 整理收藏、批量删除、重命名歌单 | 收藏/历史只有单曲 tile（`library_page.dart:40-96`），无播放全部/多选；歌单**不能重命名** |
| **听歌** | 一首放不了换一首 | `retry()` 只重试同一渠道；无换源能力 |

**「搜索框写着支持链接却做不到」是典型的虚假承诺**——与本项目一直在修的
文档漂移同类，只是这次漂移在 UI 文案里。

### 测试分层（T1 的关键经验）

最初的端到端测试用 `testWidgets` + 真实 Hive，结果**反复挂起**——测试「跑完但不结束」，
被框架超时杀掉，且**不是断言失败**，排查代价极高。

根因：`testWidgets` 把异步任务放进**伪造时钟**，而 Hive 写盘依赖真实事件循环，
`await box.put(...)` 永不完成。混用 `runAsync` 与 fake 时钟还会引入跨用例状态泄漏。

最终改为分层，各自都在可靠的时钟里：

| 层 | 文件 | 时钟 | 覆盖 |
|---|---|---|---|
| **数据层** | `test/e2e/main_flow_test.dart`（普通 `test()`） | 真实 | 落盘正确性、重启持久化、备份往返、断点续播 |
| **UI 接线层** | `test/features/library/add_to_playlist_sheet_test.dart` | 伪造（无真实 IO） | 界面是否调用正确方法、是否给出正确反馈 |

效果：442 个测试 **19 秒**跑完（此前单个 e2e 文件挂起 3 分钟）。

## 2. 明确不做（避免范围蔓延）

这些不是不重要，而是**与「日常可用」无直接关系**，做了会挤占 P1 的精力：

- WebDAV 同步（依赖 S4 收藏归一，且日常单机使用不需要）
- 自定义渠道 / 声明式源
- 均衡器 / gapless / 交叉淡入
- 桌面三栏布局、i18n
- 离线下载（涉及版权与存储策略，需单独设计）

---

## 3. 执行原则

1. **每个 D 项先写测试再实现**，测试必须能捕获回归（沿用本项目的变异验证习惯）。
2. **纯逻辑上提到 `core/`**（如链接解析），UI 只做薄接入——便于单测且不依赖 Widget 环境。
3. **不新造承诺**：改 UI 文案必须与实现同步，避免又一处漂移。
4. 每完成一项跑全量门禁（format / analyze / test），保持绿灯推进。
5. 完成后更新 README 与本文档状态，**不做「宣称完成」**。
